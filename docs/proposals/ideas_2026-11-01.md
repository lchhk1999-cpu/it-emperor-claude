## 3. 可玩性及耐玩性評估

**已有：** 每日簽到、每日／每週任務、體力、抽蛋收集、升級及三階段進化、22 個稱號、限定素材關、操練區。短期（每日）動機足夠。

**欠缺：**
1. **長期目標**：SSR 50 抽保底後就沒有追求 → #2、#11 的 UR 正好補上。
2. **進步可見度**：學生看不到「哪個課題弱」→ 建議加「學習地圖」：17 個課題的答對率星級，弱項推薦關卡。
3. **錯題重溫**：答錯的題目沒有集中重溫 → 建議「錯題本」，重溫答對可領少量金幣。
4. **社交比較**：→ #6 Game Center 排行榜（1.1）。
5. **故事吸引力**：→ #9。

**關於「沉迷」：** 建議用「健康投入」而非「沉迷」作設計目標，因為用戶是中學生，家長及學校亦會看。具體做法：獎勵綁定學習（答對、溫習弱項），不綁定遊玩時間；體力已自然限制每日長時間刷關（操練區不扣體力但沒有獎勵，鼓勵純溫習）；不做限時倒數購買壓力、不做「差一點抽中」效果、不做連續登入中斷就全部歸零的懲罰（現在簽到已是累積制）。這樣 Apple 審核及學校推廣都更安全。

## 7. 遊戲名稱「IT帝」評價
- **優點**：短、易記、易讀（廣東話「IT 帝」有「IT 皇帝／高手」的意思，學生有共鳴）；字標做圖示好看。
- **缺點**：科目正式名稱是 ICT 不是 IT；單靠「IT帝」較難被搜尋到。
- **已處理**：App Store 名稱用「IT帝：ICT 學習冒險」，補回 ICT 及學習兩個搜尋字；主畫面只顯示「IT帝」。結論：**保留**。上架前要查是否有同名 App 或商標。

## 13. 日後更新題目
1. **建議流程（不需伺服器）**：ChatGPT 出題 → Excel `status=review` → 老師審核改 approved → Claude 匯入、測試、建置 → TestFlight 給老師試 → 你批准提交 App 更新（Apple 審核約 1–3 日）。建議每 4–8 星期一次更新。
2. **遊戲內「回報題目」按鈕**：解說頁加一個按鈕，打開電郵並自動填上題目編號，學生發現錯題可直接通知你。
3. **不建議**：App 自行上網下載題目——要改私隱政策（不再是「不連網」），亦要有伺服器。

## 15. 網頁 App（PWA）先在手機試玩
- 做法：建置正式版（只含 approved 題目）加上 App 圖示、離線檔案；放到一個網址；在 iPhone 用 Safari 打開 → 按「分享」→「加入主畫面」，之後就像 App 一樣全螢幕開啟、可離線。
- iPhone 不容許網頁自己顯示「安裝」按鈕，只可以在頁面上顯示圖文教學，提示按「分享 → 加入主畫面」。
- **要放上網**：任何拿到連結的人都可以玩，等於公開了網頁版。免費方法：
  - A. 開一個**公開**的 GitHub 倉庫，只放正式版檔案，用 GitHub Pages（免費）；原本的私人倉庫不變。
  - B. Netlify 或 Cloudflare Pages（免費，要用你的電郵開帳戶）。
- 存檔：加到主畫面的網頁 App 有自己的存檔，與日後 App Store 版本不相通，可用備份碼轉移。
